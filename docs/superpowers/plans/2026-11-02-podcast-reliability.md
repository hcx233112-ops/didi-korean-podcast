# Podcast reliability implementation plan

Goal: resolve the confirmed audit findings while preserving local listening data and the current application layout.
Architecture: keep the current checkout because Windows scheduled tasks and the audio server reference this path. Separate audio/task reliability, browser playback, and authenticated cloud synchronization. No deployment or automatic Git push as part of verification.
Tech: Next.js App Router, React, TypeScript, Python, Windows Task Scheduler, Redis REST.

Accepted design: the user approved implementing the recommendations in the 2026-11-02 audit. Add a private sync secret rather than accounts; missing cloud configuration must leave local playback usable. Use timestamped records and tombstones and atomic Redis merging. Keep existing audio until replacement has passed validation. Recheck negative subtitle results after seven days. Do not redesign the UI.

- [x] Automation: first add Python regression tests for child error codes, false success, duration validation, retryable empty subtitles, locks and health checks. Run to confirm failures, then implement and rerun. Own scripts/, .github/workflows/, tests/test_automation.py. No actual Git mutation in tests.
- [x] Player: first add source-function regression tests for subtitle race/background persistence/seek and loading. Repair persistence at audio event boundaries, render the complete transcript, cancel stale requests, support keyboard and pointer seek, deadline-based timer and accessible controls. Isolate sync state in a hook, migrate legacy local state without losing data, preserve deletion timestamps, and throttle dirty writes.
- [x] Sync server: add node:test tests for configuration/authentication, bounded schema validation, storage failure, atomic merge, and deletion/reset retention. Implement lib/sync-data.ts and app/api/sync/route.ts; use a >=32-character PODCAST_SYNC_SECRET, constant-time comparison, hashed namespace and Redis EVAL. GET returns SyncData|null, POST returns {ok:true,data}.
- [x] Service worker: add mock cache/network lifetime tests; implement bounded app-specific cache, network-first video lists, guaranteed background lifetime for subtitles, and offline fallback responses.
- [x] Dependencies: upgrade the audited Next.js and affected transitive packages using the registry remediation and inspect the newly installed docs. Re-run npm audit and build. Add standard test commands and deployment/configuration documentation.
- [x] Existing media: probe source duration for the five anomalies; attempt safe validated replacement, preserve backups outside the served audio directory. Recheck the three no_transcript IDs using retryable logic. Capture any external blockers precisely.
- [x] Integration review: run node and Python regressions, TypeScript/build, production dependency audit, actual local HTTP/API and browser smoke checks, and audio Range checks. Review each subsystem against the audit and cross-review implementation quality. Never claim iOS device verification without a device.

Validation commands: npm test; python -m unittest discover -s tests -p "test_*.py"; npm run build; npm audit --omit=dev; git diff --check. Media validation uses ffprobe audio stream/duration and a full decode of replacements. The full source directory remains reviewable and no code is published automatically.

Verification results (2026-11-02): 26 JavaScript + 19 Python regressions passed; 5 Chrome integration tests passed; production build and dependency audit passed (0 vulnerabilities). All 285 audio files pass stream/duration validation, five repaired files also passed complete decoding, and one formerly empty transcript recovered 1,054 bilingual segments. Two videos still have no source subtitles and will be retried after seven days. Windows rejected in-place task registration with Access denied; all existing tasks remain enabled and point at the updated script paths. Frontend code and workflow changes have not been pushed or deployed. Private cloud sync requires the documented server-side secret.
