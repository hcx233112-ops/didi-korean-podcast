# Didi Korean Podcast

Next.js 播放器，音频由本机 Caddy 与 Cloudflare Tunnel 提供，视频列表由 GitHub Actions 更新，字幕由 Windows 定时任务生成。

## 本地运行与验证

```powershell
npm ci
npm run dev
npm test
npm run build
npm run test:e2e
npm audit --omit=dev
```

Node.js 20.9+；Python 3.11+。本地脚本依赖安装：

```powershell
python -m pip install -r scripts/requirements-automation.txt
```

音频处理需要 ffmpeg/ffprobe 在 PATH 中。先运行测试，再用 `scripts/setup-scheduler.ps1` 注册或更新任务。脚本和任务实际运行失败时返回非零退出码，`logs/*-status.log` 保存结构化状态；音频校验缓存基于文件大小、修改时间和预期时长失效。新音频先在临时目录生成，通过音轨与时长校验后替换旧文件。

## 跟读与句子本

- 字幕页右上「练习」：**单句循环**（当前句反复播，点别的句子就换一句）和**逐句跟读**（每句播完按句长停顿，留时间跟说，停顿时长可选短/中/长）。句子边界用逐帧检测，播放进度回调只有约 4 Hz，不够准。
- 页面在后台（iPhone 锁屏）时不做停顿：暂停中的页面可能不会被系统唤醒续播。循环变成无缝循环，跟读按连续播放处理；切到后台时若正在停顿会立即续播。
- 长按（桌面右键）一句：循环这句、收藏到句子本、复制、点词查词典（韩语 Naver 韩中，英语有道）。
- 首页「句子本」卡片每天换一句复习；句子本里可遮住翻译自测，▶ 只播这一句后自动停。
- 首页周条：周一到周日哪天听过（当天累计 ≥1 分钟），目标每周 4 天。
- 桌面快捷键：空格 播放/暂停，←/→ 5 秒，R 重听本句，L 开关单句循环。

## 私人云同步配置

本地收藏、备注、收听进度和句子本不依赖云同步。需要跨设备同步收藏、进度和句子本（备注不同步）时，在部署环境配置：

```text
KV_REST_API_URL=<Redis REST HTTPS endpoint>
KV_REST_API_TOKEN=<Redis REST token>
PODCAST_SYNC_SECRET=<同步口令，至少4位>
NEXT_PUBLIC_AUDIO_BASE=https://audio.yanxuan-kr.cn/
```

`PODCAST_SYNC_SECRET` 是服务端变量，不能加 NEXT_PUBLIC_ 前缀或写进仓库。设置后在每台自己的设备上，于页面右上角头像 → 设置 → 云同步中输入同一口令，之后浏览器会记住。口令可以很短，因为服务端对错误口令做全局限流：10 分钟内错 10 次即锁定 10 分钟，锁定期间正确口令也会被拒绝。这是私人单用户同步；其他访问者只使用各自本地数据。

接口要求 Authorization Bearer 密钥，使用该密钥的哈希生成独立 Redis 键，并原子合并带修改时间的记录。取消收藏、重置进度和移出句子本都保留删除标记（句子本的删除标记不留原文），旧设备不会凭更大播放位置或旧收藏复活旧数据。没有 `phrases` 字段的旧客户端和旧云端数据仍然有效，合并时保留已有句子。旧浏览器数据自动迁移；旧的未认证 `podcast-sync` 全局键不会自动导入，避免重新引入来源不明的数据。换密钥会切换云端命名空间，本地数据继续保留。

没配置 KV/口令返回 503，错误口令返回 401，错误过多返回 429，格式错误返回 400，过大数据（请求或合并后超过 512 KB、单类超过 2000 条）返回 413，存储失败返回 502。前端显示失败并保留本地更改等待重试；无变化不反复写入，正常收听时按45秒节流，并在暂停或离开页面时尝试补写。

## 自动化与媒体

- 视频抓取：`.github/workflows/update-videos.yml`。
- 字幕：Windows 每日任务为主要入口；CI 作为手动备用，避免双重生产者同时修改同一字幕。
- 无字幕结果保留检查时间，七天后自动复查；指定视频 ID 可以强制重试。
- 音频：每小时同步，校验完整性后替换；有新音频时立即触发字幕生成；巡检同时检查任务和 HTTP 服务，恢复失败会通知。
- 音频 CDN：前端请求 `<id>.mp4?v=N`，Caddy 映射到同名 `.m4a` 并仅对成功响应加缓存头，Cloudflare 默认缓存 `.mp4`。替换已发布的音频后，在 `components/podcast-app.tsx` 递增 `AUDIO_VERSION` 使边缘缓存失效。
- 调度与维护应在现有项目目录执行，任务计划、Caddyfile 引用的是该绝对路径。
- 2026-11-02 修复前的5个异常音频保留在 `.audio-repair-backups/2026-11-02/`，不进 Git、不被 Caddy 提供。

测试中的 Git、云存储、下载和任务计划均使用隔离替身，不会推送、写入真实 KV 或修改系统任务。真实 iOS 锁屏、系统回收与睡眠定时器仍需设备验证。
